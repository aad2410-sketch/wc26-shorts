# wc26-shorts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the fully-free automated pipeline that renders and posts 2–3 original WC2026 Shorts/Reels daily via GitHub Actions.

**Architecture:** Python 3.12 modules orchestrated by `src/main.py` in two phases (`render`, `publish`) with a git push between them (Instagram must cURL the rendered file from the public repo's raw URL). Data → script → TTS → ASS-karaoke-captioned ffmpeg render → YouTube Data API + Instagram Graph API.

**Tech Stack:** requests, edge-tts (fallback gTTS), Pillow, google-api-python-client + google-auth (YouTube), ffmpeg 8 (CI: ubuntu-latest preinstalled; local: present), pytest. Gemini + Pexels + football-data.org + Instagram via plain REST.

**Deviation from spec (justified):** TTS fallback is gTTS, not Kokoro — Kokoro pulls torch (~800 MB per CI run); gTTS is a 50 KB dep. Kokoro stays a documented optional upgrade. Music is optional (assets/music may be empty → VO-only mix) because CC0 music must be hand-picked by a human; SETUP.md covers it.

- [ ] Pillar prompts (recap/stats/preview/trivia/hot_take) — each instructs: hook ≤8 words, body 60–80 words spoken-style, no emojis in body, comment-bait cta, 2–4 hashtags incl `#WorldCup2026 #FIFAWorldCup`, 3 broll keywords. Match data injected as compact text lines.

### Task 5: Captions (ASS karaoke) + stat cards

- [ ] `build_ass(script, vo_duration, out_ass)`: hook event 0→1.5 s (centered, 130 pt, yellow, `\fad(80,120)` + `\t` scale pop); body words grouped 3–4 per event, timings proportional to char counts across `vo_duration`, white 95 pt with black border, lower-center (`\an2`, MarginV≈420); cta event last 1.5 s. Style block: Archivo Black, PrimaryColour `&H00FFFFFF`, hook style `&H0000E5FF` (BGR yellow), Outline 4, Shadow 2, BorderStyle 1.
- [ ] ASS timing format helper `_ts(sec)` → `H:MM:SS.cc`.
- [ ] `stat_card(lines, out_png)` (Pillow): 1080×1920 dark gradient, bold rows (e.g., `BRA 2 — 1 GER`), no logos/trademarks.
- [ ] Tests: ASS file contains N word-group Dialogue lines, monotonically increasing timestamps ≤ vo_duration+2 s; stat card PNG is 1080×1920. Run → PASS. Commit.

### Task 6: B-roll (Pexels) + render (ffmpeg)

**Files:** `src/gen/visuals.py` (pexels part), `src/render/video.py`, `tests/test_render.py`

- [ ] `fetch_broll(keywords, need_seconds, dir)` → GET `https://api.pexels.com/videos/search?query={kw}&orientation=portrait&size=medium&per_page=5` header `Authorization`; pick `video_files` entry closest to 1080 width; download until Σduration ≥ need+5 s; cycle list if short; on no key/failure return `[]`.
- [ ] `render_short(broll_paths, stat_cards, vo_mp3, ass_path, music_mp3|None, out_mp4)`:
  - Build segments: alternate b-roll clips (3 s each, `trim`, `scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920`, `setsar=1`) and stat cards (`-loop 1 -t 3` image inputs, same scale); enough segments to cover `vo_duration + 1.5`.
  - If `broll_paths` empty → synthesize segments with `color=c=0x101418:s=1080x1920:d=3` lavfi inputs (also what tests use).
  - filter_complex: `concat=n={N}:v=1:a=0[vcat]`, then `[vcat]subtitles='{ass}':fontsdir=assets/fonts[v]` (escape Windows paths), `trim` final to duration; audio: VO `[a]`, or `amix` with music at `volume=0.12`, `apad`, `-shortest`.
  - Encode: `-c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -r 30 -c:a aac -b:a 128k -movflags +faststart`.
- [ ] Offline golden test: tone VO (2 s sine), template script, synthetic color b-roll → output exists, ffprobe says 1080×1920, duration within 1 s of expected. Run `pytest tests/test_render.py -v` → PASS (this is the proof the whole render path works). Commit.

### Task 7: YouTube publisher

**Files:** `src/publish/youtube.py`, `scripts/get_youtube_token.py`

- [ ] `scripts/get_youtube_token.py`: local one-time `InstalledAppFlow.from_client_config` (`scope=["https://www.googleapis.com/auth/youtube.upload"]`, client id/secret from prompts or env) → prints refresh token.
- [ ] `upload(video, title, description, tags)` → `google.oauth2.credentials.Credentials(None, refresh_token=…, token_uri="https://oauth2.googleapis.com/token", client_id=…, client_secret=…)`; `build("youtube","v3")`; `videos().insert(part="snippet,status", body={snippet:{title (≤100 ch, append " #Shorts"), description, tags, categoryId:"17"}, status:{privacyStatus:"public", selfDeclaredMadeForKids:False}}, media_body=MediaFileUpload(video, chunksize=-1, resumable=True))`; loop `next_chunk()`; return video id. Raise nothing — return `{"ok":bool,"id"|"error"}` so one platform failing never kills the other.
- [ ] No unit test (pure API glue; integration happens at first dry-run with real creds). Commit.

### Task 8: Instagram publisher

**Files:** `src/publish/instagram.py`, `scripts/get_ig_token.py`

- [ ] `scripts/get_ig_token.py`: instructions + exchange short-lived→long-lived (`GET /oauth/access_token?grant_type=fb_exchange_token…`), and `refresh()` helper for 60-day renewal.
- [ ] `publish_reel(video_url, caption)`:
  1. `POST https://graph.facebook.com/v23.0/{IG_USER_ID}/media` `{media_type:"REELS", video_url, caption, share_to_feed:true}` → container id.
  2. Poll `GET /{container}?fields=status_code` every 30 s ×10 until `FINISHED` (`ERROR`→fail).
  3. `POST /{IG_USER_ID}/media_publish` `{creation_id}` → media id.
  - Same `{"ok":…}` result shape. Caption = title + "\n\n" + hashtags.
- [ ] Commit.
